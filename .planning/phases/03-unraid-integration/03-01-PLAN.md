<task type="auto">
  <name>Task 1: Update entrypoint and Dockerfile for PUID/PGID support</name>
  <files>entrypoint.sh, Dockerfile</files>
  <action>
The current container runs as `node` user (UID 1000, GID 1000). Unraid expects PUID=99/PGID=100 (nobody:users). The entrypoint must remap the node user's UID/GID at startup.

**Dockerfile changes:**
- Install `gosu` package in the apt-get install line (alongside dumb-init, curl, procps, git). gosu allows running commands as a different UID without the overhead/issues of su/sudo in containers.
- REMOVE the `USER node` line. The container must start as root to perform UID/GID remapping, then drop to the target user via gosu.
- Keep everything else the same (VOLUME, EXPOSE, HEALTHCHECK, ENTRYPOINT, CMD).

**entrypoint.sh changes:**
- At the top of the script (after set -e), add PUID/PGID defaulting:
  ```
  PUID=${PUID:-1000}
  PGID=${PGID:-100}
  ```
  Default PUID=1000 preserves backward compatibility for non-Unraid users. Default PGID=100 matches Unraid's `users` group.

- After the defaults, add UID/GID remapping logic:
  ```
  # Remap node user/group to match PUID/PGID
  if [ "$(id -u node)" != "$PUID" ]; then
    usermod -o -u "$PUID" node
  fi
  if [ "$(id -g node)" != "$PGID" ]; then
    groupmod -o -g "$PGID" node
  fi
  ```

- Update the chown of /home/node/.openclaw to use the new UID/GID (it already does `chown -R node:node` which will use the remapped UID/GID, so this is fine).

- Also chown /app to node:node to ensure the remapped user can read application files:
  ```
  chown -R node:node /home/node/.openclaw 2>/dev/null || true
  chown -R node:node /app 2>/dev/null || true
  ```

- Change the final `exec "$@"` to use gosu to drop privileges:
  ```
  exec gosu node "$@"
  ```

- Update the startup log to show PUID/PGID values:
  ```
  echo "PUID: $PUID, PGID: $PGID"
  ```

**Why gosu and not USER directive:** The USER directive is static. Unraid users configure PUID/PGID dynamically. The entrypoint must run as root to call usermod/groupmod, then drop to the remapped user via gosu. This is the standard pattern used by linuxserver.io images.

**Why not su/sudo:** gosu avoids TTY allocation issues and properly replaces the process (like exec). su/sudo create child processes that break signal handling with dumb-init.
  </action>
